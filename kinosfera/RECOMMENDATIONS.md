# Рекомендации КиноСферы

Реализация первого варианта для ЛР4. Главная и профиль показывают до 10 и 8
рекомендаций соответственно, карточка и плеер — похожие произведения.
Рекомендуются все опубликованные карточки, включая произведения без источника
видео. Это решение автора; отсутствие источника не изображается как возможность
запустить просмотр.

Под карточками главной и профиля причины рекомендаций не показываются. Заголовок
блока и уведомление об общей подборке при недостатке личных данных сохраняются.
Поле reason в API и журнале выдач оставлено для диагностики: это эвристическая
метка, а не разложение вклада признаков в итоговый балл.

## Граница библиотеки и приложения

Вся логика рекомендателя находится в сайте:

- `recommendation_catalog.py` переводит метаданные в признаки и переиспользует
  снимок mixdex. Его состав: год, длительность, тип произведения, множество жанров.
- `recommendation_service.py` выбирает опорные фильмы, объединяет кандидатов,
  применяет персональные ограничения, ранжирует и объясняет результат.
- `recommendation_store.py` читает актуальные взаимодействия и записывает выдачи,
  показы, клики и отказы в существующие таблицы SQLite.
- `recommendation_web.py` связывает сервис с Flask и проверяет запросы.
- `static/js/recommendations.js` обновляет карточки и подтверждает видимые показы.

mixdex используется как установленная зависимость: общее расстояние, подготовка
признаков, индекс, фильтр поиска и снимок. Код библиотеки при интеграции не
менялся. В ней нет правил положительных оценок, выбора фильмов или пользовательских
причин. Устаревшие функции `services.recommend/similar` оставлены как совместимые
обёртки над новой политикой; страницы используют новый сервис с данными SQLite.

## Алгоритм v0

На каждом запросе сервер читает таблицу ratings, позиции просмотра, watchlist,
user_preferences и not_interested текущего пользователя. ratings — источник
оценок; те же значения из user_state не добавляются второй раз.

Сначала исключаются скрытые произведения, активные отказы и оценки 1–4. По
умолчанию также исключаются уже оценённые и полностью просмотренные произведения.
Переключатель «Показывать также просмотренное и оценённое» разрешает повторный
просмотр; скрытие и активный отказ он не отменяет. Сам факт оценки не используется
как доказательство окончания сериала. Для сериала проверяется покрытие известных
эпизодов через episode_progress или episode_activity, а не одна строка progress.

Выбираются до 4 опорных произведений: сначала оценки 7–10 (оценка, время, ID),
затем просмотры с watched_seconds > 0 и (completed либо долей не менее 0.8),
затем watchlist; известная оценка ниже 7 и отказ исключают образец на любом шаге.
mixdex получает год как дискретный признак, длительность как непрерывный, тип как одиночную категорию и жанры как
множество. Веса равны; параметры масштабирования и импутации фиксированы внутри
снимка. Полностью неизвестные числовые столбцы отключаются адаптером.
Год заполняется дискретной медианой, длительность — непрерывной, тип — модой.
Отсутствующие жанры адаптер превращает в известное пустое множество, поэтому
заполнение пропущенных множеств наиболее частыми жанрами здесь не используется.

Кандидаты объединяются из 40 соседей каждого опорного фильма, 20 лучших совпадений
предпочтений с P>0 и 20 общих кандидатов. При повторном просмотре добавляются
разрешённые образцы: всего до 200 ID без этого добавления, до 204 с ним.
Для каждого кандидата заново вычисляется сходство со всеми опорными фильмами: C=max(1/(1+d)). Поэтому общий кандидат не
получает нулевое сходство только из-за своего источника.

P — среднее по заполненным группам предпочтений: Жаккар жанров, совпадение типа,
языка оригинала, хотя бы одного актёра или режиссёра по ID. Неизвестные сведения
кандидата дают 0 в соответствующей группе. T — 0.7 нормированной популярности
за 14 дней плюс 0.3 рейтинга/10; популярность считает разных пользователей с
завершённым сеансом, а при её отсутствии T равен рейтингу/10.

Итог: (0.60 C + 0.25 P + 0.15 T), делённый на сумму весов действующих компонент.
Если C или P не дали ни одного совпадения, их вес исключается для всей выдачи.
Без персональных сигналов получается общая подборка с явным пояснением. Равные
баллы разрешаются по ID. Коэффициенты выбраны вручную; качество на реальных
пользователях и выигрыш скорости перед перебором не доказаны.

## Формулы текущего v0

В индексе четыре исходных признака: год (дискретный числовой), длительность
(непрерывный числовой), тип (одиночная категория), жанры (множество).
Пусть N, K и M — непересекающиеся множества индексов оставшихся числовых,
одиночных категориальных и множественных признаков. После импутации и удаления
нулевых/константных признаков расстояние имеет вид:

$$
d(x,y)=\frac{\sum_{j\in N}w_j|z_j(x)-z_j(y)|
+\sum_{j\in K}w_j\mathbf{1}[x_j\ne y_j]
+\sum_{j\in M}w_j\bigl(1-J(x_j,y_j)\bigr)}
{\sum_{j\in N\cup K\cup M}w_j},\qquad
z_j(x)=\frac{x_j-m_j}{s_j}.
$$

Здесь m_j и s_j > 0 фиксированы для снимка, веса оставшихся признаков в v0 равны 1.
J(X,Y)=|X∩Y|/|X∪Y| для непустого объединения. В расстоянии J(∅,∅)=1,
поэтому расстояние двух известных пустых множеств равно 0. Если информативных
признаков нет, сервис отключает поиск по опорным фильмам, не вычисляя дробь 0/0.
Расстояние может превышать 1; оно определено на представлениях фильмов, поэтому
разные ID могут иметь расстояние 0.

Пусть A_u — выбранные опорные фильмы, B_u — объединённые кандидаты.
Для каждого кандидата используется одно и то же сходство, независимо от источника:

$$
C(u,i)=\max_{a\in A_u}\frac{1}{1+d(i,a)}.
$$

При отсутствии доступного сравнения C=0. Разрешённый повторный показ самого
опорного фильма получает C=1. P(u,i) — среднее совпадений по непустым группам
предпочтений; при отсутствии групп P=0. Для предпочтений жанров функция сервиса
считает J(∅,∅)=0; эта договорённость не изменяет расстояние библиотеки.

Пусть n_i — число разных пользователей с завершённым сеансом произведения за
последние 14 суток, n_max — максимум n_i среди разрешённых произведений E_u.
Q(i) — ограниченный интервалом [0,1] рейтинг, делённый на 10: средняя оценка
пользователей, если она ненулевая, иначе рейтинг карточки, иначе 0.

$$
T(i)=\begin{cases}
0.7\,n_i/n_{\max}+0.3\,Q(i),& n_{\max}>0,\\
Q(i),& n_{\max}=0.
\end{cases}
$$

Максимум популярности берётся по всему E_u после фильтров,
а не только по отобранному списку B_u. Вес сходства активен (a_C=1), если есть
опорные фильмы и хотя бы одно вычисленное сходство среди B_u; вес предпочтений
активен (a_P=1), если заполнены предпочтения и хотя бы один фильм E_u имеет P>0.
Иначе соответствующий индикатор равен 0. Для всей выдачи:

$$
S(u,i)=\frac{0.60\,a_C C(u,i)+0.25\,a_P P(u,i)+0.15\,T(i)}
{0.60\,a_C+0.25\,a_P+0.15}.
$$

Сортировка идёт по убыванию S, при равенстве — по возрастанию ID. Если оба личных
компонента отключены, S=T и показывается общая подборка. Веса подобраны вручную;
S — балл сортировки, не вероятность симпатии и не обученный прогноз.

## Обновление и сохранение

Геометрия снимка проверяется по ID и четырём признакам. При её изменении снимок
перестраивается, иначе тот же объект используется всеми запросами. JSON-копия
хранится в `.local/recommendations`, имя зависит от пути БД. Пользовательские
данные в этот снимок не входят. Для обновления оценок и отказов дерево не
перестраивается: данные читаются на каждом запросе.

Открытый блок обновляется после успешного сохранения оценок/закладок, изменения
переключателя и раз в 45 секунд в активной вкладке. Старые ответы не заменяют
новые при пересечении запросов. Это механизм обновления, а не гарантия задержки
в условиях недоступной сети или остановленного сервера.

Для вошедших пользователей recommendation_requests и событие recommendation_served
сохраняют фактически сформированный ответ, версию снимка и компоненты балла.
impressions записываются только после подтверждения браузером: не менее половины
карточки попало в видимую область активной вкладки. Клик также подтверждает показ.
Повторная отправка не создаёт дубликаты. Гость получает общую подборку без
фиктивного user_id и персональной аналитики. Принятие браузерного подтверждения
не доказывает внимательное прочтение карточки человеком.

## API

- `GET /api/recommendations?surface=home&limit=10&rewatch=0` — карточки и готовый
  HTML-фрагмент. surface=profile по умолчанию ограничивает выдачу 8 карточками.
- `POST /api/recommendations/interest` — `{"movie_id":1,"not_interested":true}`;
  false отменяет отказ. В интерфейсе есть кнопка «Не интересно».
- `POST /api/recommendations/<request_id>/feedback` —
  `{"movie_ids":[1],"action":"shown"}` или action=click для одного фильма.

POST требует входа и штатного X-CSRF-Token. Пользователь определяется по сессии,
не по переданному ID. Подтверждать можно только фильмы собственной выдачи.
При регистрации и первом входе действует экран `/auth/preferences`: три жанра
и три понравившихся произведения. Жанры записываются в `user_preferences.genres`,
произведения — в `liked_movie_ids`; завершение — в `onboarding_completed_at`.
Выбор редактируется через меню профиля. Любимые произведения становятся опорными
для поиска MixDex и исключаются из обычной выдачи до включения повторного просмотра.
История и числовые оценки при этом не создаются. Дополнительные поля предпочтений
из существующих записей сохраняются. Подробнее: [ONBOARDING.md](ONBOARDING.md).

## Установка и запуск

Установленный кинотеатр с большой рабочей базой запускается из корня проекта:

```powershell
.\.venv\Scripts\python.exe app.py --port 5050
```

Он использует `.local/cinema.sqlite3`. Приведённый ниже `run_local.py` предназначен
для отдельного рабочего файла и проверки образцов. В текущей проверенной
конфигурации используются Python 3.12, NumPy 2.1.1 и MixDex 0.1.0 по закреплённому
коммиту. Нативная часть MixDex собрана для Windows x64.

Нужны Python 3.12, Git, CMake >= 3.20 и компилятор C++20. На Windows установите
Visual Studio Build Tools с компонентом «Разработка классических приложений
на C++». Mixdex собирается из исходников при установке зависимостей.

macOS/Linux, из папки сайта:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip --isolated install --no-user -r requirements-recommendations.txt
.venv/bin/python run_local.py --sample /путь/к/cinema_sample.sqlite3
```

Windows (PowerShell), из папки сайта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip --isolated install --no-user -r requirements-recommendations.txt
.\.venv\Scripts\python.exe run_local.py --sample "C:\путь\к\cinema_sample.sqlite3"
```

В requirements-recommendations.txt закреплён полный хеш коммита Mixdex
`96c7f2e426c4a002316972550be8dba68b147b19` из отдельного
[репозитория](https://github.com/AlSky361/Mixdex). Локальная папка библиотеки не
нужна; пакет с таким именем из PyPI не используется. Новый код библиотеки
подключается только после явного обновления хеша и повторной проверки сайта.
Такую установку по коммиту поддерживает [pip](https://pip.pypa.io/en/stable/topics/vcs-support/).
Для проверки согласованности установленных зависимостей выполните
`python -m pip check` с Python вашего окружения.

После установки и первого запуска с образцом рабочая БД сохраняется;
для повторного запуска достаточно `.venv/bin/python run_local.py`. Адрес по умолчанию — http://127.0.0.1:5057/.

run_local.py копирует образец только при отсутствии рабочей БД и не перезаписывает
её на повторном запуске. Оригинал не используется для записи. Зарегистрируйте
свой тестовый аккаунт на странице сайта: пароли существующих аккаунтов образца
не изменялись. Оцените несколько фильмов на 7–10 и вернитесь на главную.

Для работы самого плеера нужны дополнительные зависимости из requirements.txt
и FFmpeg/FFprobe. Проверки рекомендаций работают без настоящего libtorrent;
медиатесты используют существующий эмулятор. Отсутствующие в полученном архиве
загруженные постеры заменяются доступной обложкой или placeholder; отсутствующее
видео главного баннера не запрашивается.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -p "test_*.py" -v
.venv/bin/python tests/check_recommendation_sample.py /путь/к/cinema_sample.sqlite3
.venv/bin/python -m pip --isolated install --no-user -r requirements-test-recommendations.txt
.venv/bin/python tests/e2e_recommendations.py --database /путь/к/cinema_sample.sqlite3 --channel chrome
```

Без --channel Playwright использует свой Chromium; его устанавливают отдельно
командой `python -m playwright install chromium`. Браузерный сценарий проверяет
десктоп и мобильную ширину, подменяя внешние постеры локальной фикстурой.
Исключения аппаратного кодирования и sparse-файлов в полном наборе зависят от ОС.
Тесты мини-БД выполняются на временной копии. Замеры Flask test_client не равны
проверке всей нагрузки ТЗ с двумя комнатами просмотра и реальными браузерами.

Архитектурные ориентиры: [разделение кандидатов и ранжирования](https://developers.google.com/machine-learning/recommendation/overview/types),
[тестирование Flask](https://flask.palletsprojects.com/en/stable/testing/).
Конкретная политика v0 — реализация проекта, не алгоритм, приписываемый этим источникам.
