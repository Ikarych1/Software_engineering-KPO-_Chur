# Тестовая БД, совместимая с проектом — версия 3

**Актуальный файл: [cinema_test.sqlite3](cinema_test.sqlite3).**

Обновление от 01.11.2026: этот набор также перенесён в рабочую базу кинотеатра
с сохранением существующих аккаунтов и их данных. Сам исходный файл остаётся
отдельным и не изменяется. В рабочей базе дополнительно есть служебная таблица
`dataset_imports`; подробности и отчёт описаны в [инструкции по переносу](../../DATASET_MERGE.md).

В рабочей базе проекта и этой тестовой базе теперь **одинаковая структура: 30 таблиц и представление `episode_activity`**. Совпадают названия и порядок колонок, SQL-типы, значения по умолчанию, первичные и уникальные ключи, индексы и внешние связи. Сравнение выполнено по фактическим SQLite-метаданным обеих баз, а тестовый файл открыт штатным `Store` из `database.py`.

В тестовой базе **50 000 пользователей, 3 054 произведения и 6 219 466 оценок**. Исходные оценки и даты сохранены, ID пользователей преобразованы в целые числа. Настоящие аккаунты проекта, их пароли, переписка и платежи в тестовый файл не переносились.

## Что изменено в проекте

Существующие 19 таблиц и их колонки сохранены. Миграция добавила 11 таблиц для информации, которую прежняя схема не могла хранить:

| Новые таблицы | Назначение |
|---|---|
| `user_preferences` | Выбранные жанры, типы контента, языки, длительность, актёры и режиссёры |
| `not_interested` | Состояние «не интересно», причина и дата |
| `episodes` | Метаданные серий независимо от наличия видеофайла |
| `watch_sessions` | Отдельные сеансы, повторы, позиции, время, досмотр и причина остановки |
| `recommendation_requests`, `impressions`, `clicks` | Запрос выдачи, позиции и клики |
| `searches` | Поисковые запросы и выбранные произведения |
| `bookmark_events` | Датированная история добавления/удаления закладок |
| `tags` | Пользовательские теги |
| `events` | Общий журнал с JSON payload |

`episode_activity` — вычисляемое представление прогресса всех серий из сеансов. Оно не является второй таблицей действий.

Добавлены индексы для связей и истории пользователей, а также покрывающий индекс рейтингов для штатной статистики сайта. Определения находятся в `engagement_schema.py` и автоматически устанавливаются при создании `Store`. Отдельная команда миграции `migrate_engagement.py` сначала делает SQLite-резервную копию и затем атомарно добавляет структуры. При уже выполненной миграции повторное открытие `Store` безопасно.

Первоначальная миграция структуры рабочей базы уже применена. На том этапе содержимое прежних таблиц проверено до/после по хешам значений строк: **оно не изменилось**. Её резервная копия и отчёт находятся в `.local/backups/` и `.local/engagement_migration.json`. Последующий перенос тестовых пользователей и взаимодействий в рабочую базу описан отдельно в `DATASET_MERGE.md` и `.local/test_dataset_import.json`.

Это подготовка хранения данных. Сбор новых реальных показов/кликов интерфейсом и обучение рекомендательной модели этой работой не добавлялись.

## Как преобразованы данные

| Исходный набор v2 | Формат проекта v3 |
|---|---|
| `movies` | `films`; карточка строго соответствует `MediaItem` в JSON `data`, расширенные признаки и изображения — в JSON `art` |
| `users.user_id = ml32m_000123` | `users.id = 123`, тип INTEGER; стандартные поля аккаунта, роли и подписки |
| `ratings` | Штатные `(user_id, movie_id, score, updated_at)` с составным PK; те же оценки продублированы в `user_state.data.ratings`, как требует проект |
| `watched`, `watchlist`, `clips` | Штатные списки в `user_state.data`; клипы используют `movieId`, `movieTitle`, `start`, `end`, `pinned`, `createdAt` |
| Профильные предпочтения | `user_preferences`; обычное сохранение UI-настроек не удаляет их |
| `progress` | Штатная таблица с `updated_at`, `hidden` и реальным `file_id`, если он существует |
| `episode_progress` | 91 запись с реальными видеофайлами — в штатной таблице; все 13 675 снимков доступны в `episode_activity` |
| `watch_sessions` | Новая таблица, связанная 1:1 с записью штатной `views` через `view_id` |
| `rooms`, `room_members` | Штатные `rooms.code`, `host_id`, JSON `settings/state`; членство использует `code`, `joined_at`, `last_seen` |
| События создания/входа/выхода комнаты | Также отражены штатными системными сообщениями `room_messages`; вымышленные тексты пользовательского чата не добавлялись |
| `movie_mapping` | Соответствия MovieLens сохранены в `films.art.movielens_ids` |
| `movie_stats`, `user_activity` | Получаются запросами из оценок, просмотров, событий и прогресса; отдельные дублирующие таблицы не создаются |

Коды комнат преобразованы в шестисимвольные коды приложения. Все структурные ссылки на пользователей и комнаты преобразованы согласованно, включая JSON payload событий. Внешние идентификаторы оценок и прежнее разбиение train/validation/test сохранены в вспомогательном `rating_sources.csv.gz`, который связывается по `(user_id, movie_id)` и не меняет прикладную схему.

Даты взаимодействий и просмотра приведены к **Unix seconds REAL**, как в проекте. `users.created_at` хранится в его штатном текстовом формате UTC. Отдельных колонок «реальный рейтинг»/«синтетический рейтинг» и флагов генерации нет.

## Метаданные и наличие видео

В `films.data` находятся поля `id`, `title`, `description`, `genres`, `year`, `country`, `rating`, `duration_min`, `age_rating`, `is_hidden`, `kind`. Другие признаки находятся в `films.art`: `imdb`, `imdb_votes`, `kp`, `kp_votes`, `tmdb_rating`, `tmdb_votes`, `original`, `tagline`, `actors`, `cast`, `director`, `directors`, `countries`, `country_codes`, `original_language`, `spoken_languages`, `content_type`, `collection_id`, `collection_name`.

Формат карточки декодируется существующим `Store.decode_film` без адаптера и без изменения dataclass `MediaItem`. Идентификаторы произведений совпадают с каталогом проекта. Из исходной базы перенесены только относящиеся к каталогу технические данные источников и анализа медиа; новые видеофайлы и торрент-ссылки не выдумывались.

`films.episodes` и штатный `episode_progress.file_id` относятся к **реальным файлам плеера**. Новая `episodes` описывает метаданные серий; её `file_id` может быть NULL. Для отсутствующего видео не создаётся фиктивный файловый индекс. При этом история просмотра и прогресс такой серии сохраняются через `watch_sessions` и представление `episode_activity`.

## Открыть в самом сайте

`app.py` теперь поддерживает отдельный путь через `CINEMA_DATABASE`. Без этой переменной приложение продолжает использовать `.local/cinema.sqlite3`.

Для отдельного тестового запуска из корня проекта:

```powershell
$env:CINEMA_DATABASE = 'C:\Users\sasha\Desktop\lab_2\datasets\cinema_project_v3\cinema_test.sqlite3'
.venv\Scripts\python.exe app.py --port 5051
```

Это даст приложению возможность менять тестовый файл при входе и работе с профилем. После завершения тестового процесса убери переменную в этой консоли:

```powershell
Remove-Item Env:CINEMA_DATABASE
```

Данные для входа в тестовые профили — в [TEST_LOGIN.md](TEST_LOGIN.md). Для них сгенерирован один общий тестовый пароль с корректным хешем scrypt; первый профиль — ADMIN. Это отдельные вымышленные учётные записи.

## Проверки и источники

- [validation.json](validation.json): точное совпадение схемы с проектом, хеш всех 6 219 466 оценок, 50 000 штатных JSON-профилей, коллекции, прогресс серий, связи и полная проверка целостности SQLite.
- [app_validation.json](app_validation.json): вход и страницы настоящего Flask-приложения на копии полного тестового файла; основной файл при этой проверке не меняется.
- [ERD](erd/index.html), [diagrams.net](erd/cinema_test.drawio), [физический SQL](schema.sql), [описание ERD](erd/ERD.md).
- `schema_signature.json`: метаданные общей структуры; `cinema_test.sqlite3.sha256`: контрольная сумма проверенного файла.

Основа пользовательских оценок и тегов — MovieLens 32M, ограниченный каталогом проекта; остальные взаимодействия моделировались в прежнем наборе. Метаданные — снимок каталога, TMDB и IMDb с ранее заполненными пропусками. Значения Кинопоиска не являются подтверждёнными актуальными данными. Первичные значения не генерировались заново при преобразовании структуры. Происхождение и условия первоисточника сохранены в предыдущем наборе v2 и приложенном `MOVIELENS_SOURCE_README.txt`.

Повторная сборка из корня проекта:

```powershell
.venv\Scripts\python.exe datasets/cinema_project_v3/build_database.py
.venv\Scripts\python.exe datasets/cinema_project_v3/validate_database.py
.venv\Scripts\python.exe datasets/cinema_project_v3/erd/build_erd.py
```

Сборщик не перезаписывает уже существующую базу. Для повторного независимого набора используй копию каталога назначения. Работающий проект и отдельный тестовый набор используют одну и ту же схему хранения.
