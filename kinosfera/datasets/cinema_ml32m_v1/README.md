# Отдельный тестовый датасет КиноСферы + MovieLens 32M

**50 000 пользователей · 3 054 произведения только из каталога проекта.**
Снимок каталога: **31 октября 2026 года**. Все таблицы лежат в `data/` в формате
**CSV.gz, UTF-8**; вложенные списки и объекты записаны как JSON внутри ячеек.
Это отдельный набор для тестовой обработки. Он не импортирован в рабочую базу
и не подключён к сайту. Рекомендательная модель не разрабатывалась и не обучалась.

## Что реально, а что сгенерировано

**Реальная основа:** официальный [MovieLens 32M](https://grouplens.org/datasets/movielens/32m/).
Из него отобраны оценки и теги только для совпавших с каталогом произведений.
Сначала сопоставлены IMDb ID; TMDB ID используется только в пространстве фильмов.
Противоречивые соответствия не принимаются. Числовые ID MovieLens не считаются ID нашего каталога.

- 2 570 произведений каталога сопоставлены с MovieLens.
- Случайно и воспроизводимо выбраны 50 000 обезличенных пользователей,
  имеющих минимум 20 совпавших исходных оценок.
- Сохранены **6 184 366 реальных оценок** и **456 375 реальных пользовательских тегов**.
- Оценка 0,5–5 переведена в 1–10 умножением на два; исходная оценка и дата сохранены.
- 14 дублирующих оценок, возникших из-за нескольких исходных ID одного произведения,
  сведены к последней оценке пользователя этому произведению.
- Остальные произведения каталога присутствуют в метаданных и могут участвовать
  в синтетических действиях. Новые фильмы вне каталога не добавляются.

**Синтетика:** клики, показы, поиск, история воспроизведения, закладки, «не интересно»,
клипы, отзывы, комнаты, дополнительные оценки и профили предпочтений.
Они нужны для проверки обработки событий и связей; их нельзя представлять
как настоящие действия пользователей MovieLens или пользователей сайта.

**Метаданные:** взяты из `films.data`, `films.art`, существующего кеша TMDB и
локального официального набора рейтингов IMDb. Недостающие текстовые поля,
языки, возрастные ограничения и отдельные рейтинги дополнены генерацией.
Каждое такое поле перечислено в `movies.synthetic_fields`, его источник — в
`movies.metadata_provenance`. **Все рейтинги и числа голосов Кинопоиска в этом
датасете синтетические**, а не актуальные данные Кинопоиска.
Отсутствующая франшиза/коллекция оставлена пустой: отдельному произведению не
приписывается выдуманная франшиза для заполнения поля.

## Ключи, даты и единицы

- `movie_id` всегда совпадает с существующим **films.id** снимка каталога.
  Единственное исключение по пустоте — события поиска/онбординга без конкретного фильма:
  в них movie_id пуст, а не ссылается на вымышленное произведение.
- `user_id` имеет вид `ml32m_000123`. Это обезличенный ID из внешнего набора,
  **не ID аккаунта КиноСферы**. Реальные email, имена, хеши паролей и переписка
  двух пользователей сайта в набор не переносились. Тестовые email заканчиваются `@example.invalid`.
- `source_movie_id` — исходный ID MovieLens. Он не совпадает с нашим movie_id.
- `episode_id` — ID эпизода внутри датасета. `source_file_id` заполнен, если
  эпизод связан с существующим файлом серии в каталоге.
- Даты `rated_at`, `created_at`, `registered_at` и даты тегов — **Unix seconds UTC**.
  Поля, заканчивающиеся на `_ms`, — **Unix milliseconds UTC**.
- Время/позиция воспроизведения и длительность в таблицах сеансов/прогресса — **секунды**.
  `movies.duration_min` — **минуты**.
- Пустая скалярная ячейка — неизвестное/неприменимое значение, не ноль.
  Массивы/объекты нужно разбирать как JSON; отсутствие списка записывается `[]`.
- Порядок строк файлов не обещает глобальную сортировку по времени.
  Для последовательной обработки действий сортируйте их по дате и при необходимости event_id.

Полный перечень столбцов — в `schema.json`; количества, источники и контрольные
суммы — в `manifest.json`. Результат независимой проверки — `validation.json`.

## Правила генерации и важные границы интерпретации

Генерация воспроизводима: seed **20261031**. На пользователя приходится три
выдачи по десять произведений. В каждой выдаче есть 1–3 клика; не каждый клик
приводит к просмотру. Есть отдельные паузы, перемотки, буферизация, продолжения
и повторные просмотры. Причины остановки: `finished`, `lost_interest`,
`technical_problem`, `user_exit`. Длительность сеанса согласована с просмотренным
временем, паузами и буферизацией. Закладки в итоговом списке воспроизводятся из
событий add/remove. Участники комнат связаны с сеансами одного произведения.

Профиль предпочтений выводится только из **train-части реальных оценок** с
добавлением тестовых настроек. Это моделируемый онбординг, а не восстановленная
анкета настоящего пользователя. В профилях нет настоящих контактных данных.
Тексты отзывов шаблонные, а не настоящие отзывы MovieLens.

Для сериалов использованы 64 уже существующие записи серий и добавлена
синтетическая структура для остальных: до трёх сезонов и десяти эпизодов на сезон.
Это модельный поднабор, не официальный полный список эпизодов каждого сериала.
Длительность серии взята из среднего значения карточки сериала, а не измерена
по конкретному видеофайлу. Идентичность эпизода и происхождение списка отражены
в episodes.source/is_synthetic; сгенерированные эпизоды явно помечены.

Наличие источника в настоящем каталоге и возможность просмотра в симуляции
разделены: **has_video_source** — реальный признак из каталога,
**simulated_playback_available=1** — допущение тестового плеера для всех тайтлов.
Синтетические сеансы не означают, что видео существует или воспроизводится на сайте.
Торренты, magnet-ссылки и видео в набор не включены.

### Для тестовой обработки и для оценки модели — разные режимы

Реальные оценки имеют разбиение по времени каждого пользователя:
**train 4 927 399**, **validation 615 611**, **test 641 356**.
Одинаковые временные метки упорядочены по ID произведения; строгой временной
разницы на границе равных меток это не создаёт.
Синтетические оценки находятся отдельно, со split `synthetic_only`.

Реальные оценки относятся к истории MovieLens до октября 2023 года, а метаданные
каталога — к снимку 2026 года. Синтетическое поведение в основном моделирует
октябрь 2026 года; сгенерированные отзывы привязаны к датам исходных train-оценок.
Это не полностью согласованный исторический снимок сервиса.

Для проверки форматов, связей, агрегаций и нагрузки можно использовать весь набор.
Для измерения качества на настоящих людях используйте **только реальные**
ratings.csv.gz с их разбиением и учитывайте дату доступности признаков.
Синтетические клики/отзывы/предпочтения не являются независимым подтверждением
качества рекомендаций: они получены по заданным сценариям и связаны с train-оценками.

## Источник, лицензия и воспроизведение сборки

Все четыре исходных CSV MovieLens проверены по официальным MD5 из README.
Условия использования и требуемая ссылка на публикацию сохранены целиком в
`MOVIELENS_SOURCE_README.txt`. Набор рассчитан на учебные/исследовательские тесты;
для коммерческого использования MovieLens действуют отдельные условия его авторов.

Citation: F. Maxwell Harper and Joseph A. Konstan. 2015.
The MovieLens Datasets: History and Context. ACM TiiS 5(4), Article 19.
https://doi.org/10.1145/2827872

Скрипты сборки и проверки не импортируют app.py и не запускают приложение.
Они открывают исходную SQLite-базу с `mode=ro` и `PRAGMA query_only=ON`.
Совпадение SHA-256 основного файла базы до и после сборки проверяется отдельно.

Для повторной сборки используйте новую пустую папку с копией build_dataset.py,
скачайте официальный ml-32m.zip и задайте `--database` и `--archive` при необходимости.
Повторная запись существующих CSV запрещена, чтобы случайно не затереть готовый набор.
Проверка готового набора:

```powershell
.venv\Scripts\python.exe datasets/cinema_ml32m_v1/validate_dataset.py
```

На другом компьютере готовые CSV можно проверять без доступа к исходной базе:
`python validate_dataset.py --offline`. Проверка тогда использует список допустимых
ID в манифесте, а сравнение с живой базой явно пропускается.

Исходный полный архив MovieLens не входит в выдаваемый набор. В таблицах сохранены
только произведения, присутствующие в снимке каталога проекта.
