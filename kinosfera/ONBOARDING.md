# Первоначальные предпочтения

После регистрации открывается `/auth/preferences`. Пользователь выбирает ровно
3 жанра и 3 понравившихся фильма или сериала. В подборке есть поиск по русскому
и оригинальному названию и загрузка следующих страниц. Выбранные произведения
сохраняются при поиске, даже когда их нет в текущем списке результатов.

Старые аккаунты без `onboarding_completed_at` проходят тот же экран при новом
входе или открытии страницы в уже существующей сессии. Для API сервер возвращает
HTTP 428 с `onboarding_required` и адресом настройки. Проверка действует и на
`/api/profile/state`; для POST сохраняется штатная защита CSRF. Восстановление
пароля и выход из аккаунта доступны до завершения настройки.

Выбор хранится в `user_preferences`:

- `genres` — JSON-массив выбранных жанров;
- `liked_movie_ids` — JSON-массив ID понравившихся произведений;
- `onboarding_completed_at` — время завершения настройки, Unix seconds;
- `updated_at` — время последнего изменения предпочтений.

Остальные поля этой таблицы сохраняются при редактировании. Выбор не создаёт
числовые оценки, закладки или отметки просмотра. Для изменения достаточно
открыть меню через аватар → «Мои предпочтения».

MixDex использует любимые произведения как примеры для поиска похожих карточек;
совпадение жанров учитывается политикой рекомендаций приложения. Уже выбранные
любимые произведения не повторяются в обычной подборке; переключатель повторного
просмотра разрешает их показывать.

# Большая рабочая база

Каталог и коллекции выводятся по 36 карточек на страницу. Жанровые ленты на
главной ограничены 12 карточками. Админка показывает пользователей по 50 записей,
а в обзоре загружает пять последних аккаунтов.

Средние оценки и числа просмотров/отзывов кэшируются внутри `Store`.
`cache_versions` и триггеры SQLite меняют поколение кэша при изменениях таблиц
`ratings`, `views`, `reviews`, в том числе через отдельное подключение DBeaver.
Обычные изменения настроек, предпочтений, показов и кликов кэш не сбрасывают.
Первый подсчёт после запуска или изменения статистики проходит по большой
таблице; следующие запросы используют готовый результат.

Миграция добавляет две колонки предпочтений, служебную таблицу и триггеры.
Переимпорт MovieLens и замена рабочей базы для этого не требуются.

Перед обновлением сохранены исходники и SQLite-копия в `.local/backups/`.
Проверка рабочей базы и замеры находятся в `.local/mixdex_enable_report.json`.
Браузерные проверки работают на временных копиях малой базы:

```powershell
.\.venv\Scripts\python.exe tests/e2e_onboarding.py
.\.venv\Scripts\python.exe tests/e2e_recommendations.py --database datasets/cinema_sample/cinema_sample.sqlite3 --channel msedge
```

Первый сценарий использует установленный Edge и проверяет новый аккаунт,
старый аккаунт без предпочтений, сохранение выбора при поиске и экран шириной
390 px. Второй проверяет обновление выдач, отказы, оценки и повторный просмотр.

При обычном запуске статистика и индекс прогреваются до открытия HTTP-порта.
Проверены 98 целевых тестов и два браузерных сценария. Полный совместный запуск
178 тестов выявил четыре сбоя медиасценариев; эти же четыре сценария отдельно
прошли как на исходной, так и на обновлённой версии. Изоляция общего медианабора
требует отдельной проверки; соответствующие логи находятся в
`tmp/mixdex-tests/unittest-local-network.log` и `tmp/mixdex-tests/media-isolated.log`.
