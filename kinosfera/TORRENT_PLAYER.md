# КиноСфера: потоковый BitTorrent-кинотеатр с совместным просмотром

## Запуск

Из папки проекта в PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe app.py --port 5050
```

Нужны Python 3.12 и `ffmpeg`/`ffprobe` в PATH (или переменные `FFMPEG_PATH`/`FFPROBE_PATH`).
Откройте [регистрацию](http://127.0.0.1:5050/auth/register). Первый аккаунт получает роль ADMIN.

Чтобы друзья в локальной сети могли зайти в комнату: `app.py --host 0.0.0.0 --port 5050`,
а им открыть `http://<IP-вашего-компьютера>:5050`. Для двух аккаунтов на одном компьютере
используйте два разных браузера или окно инкогнито: вход хранится в cookie.

## Как устроен стриминг (почему быстро)

| Было | Стало |
|---|---|
| Каждый зритель запускал свою сессию libtorrent (свой DHT, свои пиры) | **Одна настроенная сессия на сервер**; DHT-таблица сохраняется между запусками (`session.state`) |
| Один фильм у пяти зрителей скачивался пять раз | **Один торрент на фильм** для всех зрителей и комнат |
| При паузе и каждые 64 МиБ торрент удалялся и добавлялся заново (соединения терялись) | Торрент живёт, пока его читают; при паузе загрузка вперёд продолжается |
| Окно приоритета — 3 части | **Окно по битрейту**: ~12 с с дедлайнами (`set_piece_deadline`), до 120 с с высоким приоритетом, остальной файл — фоном |
| Любой файл перекодировался; на каждый 6-секундный сегмент запускался новый FFmpeg с повторным анализом | **Прямой поток** оригинала для MP4/WebM (и MKV с H.264 в Chrome/Edge), анализ — один раз с кешем в БД; для остальных форматов — **один непрерывный общий HLS-процесс** |
| Данные читались только через `read_piece` (копирование через очередь событий) | Готовые части читаются с диска и проверяются по SHA-1 из .torrent; `read_piece` — запасной путь |
| Повторный просмотр скачивался заново | **Кеш на диске + resume data**: повторный запуск мгновенный, без перехеширования |
| Фильм целиком оседал на диске (2,9 ГБ на один фильм) | **Скользящее окно**: на диске только начало/конец файла, 30 с позади и окно впереди — обычно 100–400 МБ даже для 4K |

### Скользящее окно на диске

По умолчанию фильм не скачивается целиком. Просмотренные части освобождаются: раз в несколько
секунды движок проверяет, сколько скачанного лежит вне окна. Если набралось 512 МиБ и окно впереди
у зрителей уже скачано (или накопилось 1,5 ГиБ), он «прокалывает» эти места в файле (разреженный файл
NTFS/ext4) и на долю секунды переподключает раздачу, отметив части как нескачанные. Переподключение
рвёт соединения с пирами (скорость на 10–60 с проседает), поэтому делается редко и в спокойные
моменты. Безопасно освобождать место без переподключения нельзя: libtorrent продолжила бы раздавать
«дырки» другим участникам. Перемотка назад дальше окна просто докачивает нужный кусок заново. Просмотренные HLS-сегменты (для AVI и других
перекодируемых форматов) тоже удаляются, когда остаются позади зрителя; FFmpeg готовит не
больше 4 минут вперёд.

После перемотки место, откуда вы ушли, держится на диске ещё 10 секунд (можно сразу вернуться),
затем удаляется. То же с вариантом качества или озвучки, с которого вы переключились, и с
местами, которые никто больше не читает. Закрыли плеер — через ~10 секунд на диске остаются
только начало и конец файла. Обратите внимание: Проводник в колонке «Размер» показывает полный
размер серии — это разреженный файл; реально занятое место — в «Свойства → На диске».

Дополнительно: первыми загружаются начало и конец файла (индекс MP4/MKV/AVI), к раздаче
добавляются публичные трекеры, включены UPnP/NAT-PMP/LSD, ускорено установление соединений
и перезапрос медленных блоков. Плеер открывает страницу фильма заранее — пока вы нажимаете
«Смотреть», движок уже подключается к пирам. Комната «прогревает» фильм сразу при создании.

Плеер показывает скорость, число пиров, сколько секунд загружено вперёд и способ доставки.
Позиция сохраняется каждые ~8 секунд: «Продолжить с 42:10» работает на любом устройстве.

### Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CINEMA_CACHE_LIMIT_GB` | 20 | Лимит кеша фильмов; старые удаляются автоматически |
| `CINEMA_BACKGROUND_DOWNLOAD` | 0 | `1` — скачивать и хранить фильм целиком (старое поведение: повторный просмотр без докачки, но весь фильм на диске) |
| `CINEMA_KEEP_BEHIND_SECONDS` | 30 | Сколько секунд уже просмотренного держать на диске для перемотки назад |
| `CINEMA_SEEK_GRACE_SECONDS` | 10 | Сколько держать место, с которого перемотали (и всё, что перестали читать) |
| `CINEMA_HLS_AHEAD_SECONDS` | 240 | На сколько FFmpeg перекодирует вперёд зрителя |
| `CINEMA_HWACCEL` | auto | Перекодирование на видеокарте: `auto` (AMD AMF → Intel QSV → NVIDIA NVENC, проверяется при запуске), `amf`/`qsv`/`nvenc` или `off` — только процессор |
| `CINEMA_HLS_MAX_JOBS` | 3 | Сколько FFmpeg одновременно на весь сайт |
| `CINEMA_TRIM_FORCE_MB` | 1536 | Освобождать место даже без «спокойного момента» при таком объёме |
| `CINEMA_TRIM_STEP_MB` | 512 | Освобождать место порциями не меньше этой (меньше — чаще короткие переподключения) |
| `CINEMA_READAHEAD_SECONDS` | 120 | Насколько вперёд загружать с высоким приоритетом |
| `CINEMA_LISTEN_PORT` | 6881 | Порт BitTorrent (откройте его в брандмауэре для входящих пиров) |
| `CINEMA_UPLOAD_LIMIT_KBPS` / `CINEMA_DOWNLOAD_LIMIT_KBPS` | 0 | Ограничения скорости (0 — без ограничений) |
| `CINEMA_EXTRA_TRACKERS` | 1 | Добавлять публичные трекеры |
| `CINEMA_HLS_HEIGHT` / `CINEMA_HLS_PRESET` | 720 / veryfast | Качество и скорость перекодирования |
| `CINEMA_HLS_CACHE_GB` | 4 | Лимит готовых HLS-сегментов на диске |

## Совместный просмотр

«Смотреть вместе» на странице фильма, в плеере или на главной создаёт комнату с кодом
из 6 символов. Вход — по ссылке или коду на странице «Смотрим вместе».

- Сервер хранит состояние плеера, события приходят через Server-Sent Events.
- Клиент оценивает смещение часов относительно сервера и корректирует рассинхрон:
  мелкий — ускорением/замедлением на несколько процентов, крупный — перемоткой.
- «Ждать всех»: если у участника видео догружается дольше 2,5 с, комната ставится на паузу
  и продолжает сама, когда все готовы.
- Чат (сохраняется), реакции поверх видео, список участников со статусами
  («смотрит», «догружает видео…», «отстаёт на 5 с»), передача роли хоста, смена фильма,
  закрытие входа, режим «управляют все». После завершения чат остаётся в истории комнат.

## Пользователь

Профиль: обзор со статистикой и любимыми жанрами, «Продолжить просмотр», история с
прогрессом, оценки, «Буду смотреть», отзывы, клипы, «Компания» (люди из ваших комнат и
совпадение вкусов по оценкам), мои комнаты, демо-подписка с историей операций (у каждого своя),
настройки (имя, «о себе», цвет аватара, пароль).
Главная: «Продолжить просмотр», «Можно смотреть сейчас», персональные рекомендации по оценкам
и просмотрам, популярное и высоко оценённое зрителями. Поиск учитывает актёров и режиссёров.
Карточка фильма: оценка зрителей КиноСферы, отзывы, качество видео (разрешение, кодеки, размер),
похожие фильмы. Клавиши в плеере: Пробел, ←/→, F, M.

### Восстановление пароля по почте

На странице входа — ссылка «Забыли пароль?» (`/auth/forgot`). На почту приходит одноразовая
ссылка `/auth/reset/<токен>`, действующая 1 час. В базе хранится только SHA-256 токена; после
смены пароля все сеансы и остальные ссылки аккаунта аннулируются (смена пароля в профиле тоже
отзывает ссылки). Ответ одинаков для существующих и несуществующих адресов; не чаще одного
письма в минуту на аккаунт и 5 запросов за 15 минут с одного IP.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CINEMA_SMTP_HOST` | — | SMTP-сервер. Если не задан, письма сохраняются в `.local/outbox/*.eml`, путь пишется в лог |
| `CINEMA_SMTP_PORT` | 587 | Порт (465 — сразу SSL) |
| `CINEMA_SMTP_SECURITY` | `starttls` (`ssl` для 465) | `starttls`, `ssl` или `none` |
| `CINEMA_SMTP_USER` / `CINEMA_SMTP_PASSWORD` | — | Логин и пароль (для Gmail/Яндекса — пароль приложения) |
| `CINEMA_SMTP_FROM` | `CINEMA_SMTP_USER` | Адрес отправителя, например `КиноСфера <cinema@example.com>` |
| `CINEMA_PUBLIC_URL` | адрес из запроса | Адрес сайта для ссылок в письмах, например `http://192.168.1.10:5050`. Задайте его при `--host 0.0.0.0`, чтобы подделанный заголовок Host не испортил ссылку |

## Администратор

Вкладки «Обзор» (метрики, график загрузки в реальном времени, топ просмотров),
«Фильмы» (фильтры, просмотры и оценки), «Раздачи» (активные торренты, зрители, кеш на диске
с удалением), «Пользователи» (поиск, роли, блокировка, сброс сеансов), «Отзывы» (модерация),
«Комнаты» (закрытие). В карточке фильма: .torrent **или magnet-ссылка** (метаданные
получаются от пиров), загрузка постера и кадра для главной, «Проверить раздачу» (пиры,
скорость, качество, способ воспроизведения — заодно прогревает фильм), удаление фильма.

### Сериалы

В карточке выберите тип «Сериал» и загрузите раздачу с сериями (как у сезонных раздач:
папка с файлами `S01E01`, `1x02`, «Сезон 1 / Серия 2» и т. п.). Сезоны и номера серий
распознаются по именам файлов; в таблице под источником их можно поправить, задать
названия серий, отключить лишние файлы или «Распознать заново». Длительность в карточке —
длительность одной серии.

**Сезоны из разных раздач.** Обычно каждый сезон — отдельная раздача. В карточке сериала, под
таблицей серий, есть блок «Добавить сезон»: выберите .torrent (или вставьте magnet и нажмите
«Прочитать»), при необходимости укажите номер сезона и нажмите «Добавить сезон». Серии
добавятся к карточке; если такие номера серий уже есть — появится понятная ошибка. Таблица
серий сгруппирована по раздачам, добавленный сезон можно убрать кнопкой «Убрать».

**Как видно, что раздача подгружается.** Сразу после выбора .torrent сайт читает его и
показывает: имя раздачи, число файлов и размер, найденные сезоны и серии (со списком) и
предупреждения (например, файлы без номера серии). Magnet-ссылка читается в фоне, с таймером:
«Ищем участников раздачи… 12 с». После сохранения проверка раздачи запускается сама и
показывает этапы: раздача прочитана → участники (сколько, скорость; предупреждение, если за
45 секунд никого нет) → загрузка начала видео → анализ (качество, кодек, аудиодорожки). Для
сериала можно выбрать, какую серию проверить.

Зрители видят в каталоге бейдж «Сериал» и число серий, фильтр «Сериалы», на странице —
вкладки сезонов со списком серий и отметками просмотра. Прогресс хранится по каждой серии:
«Продолжить» ведёт на начатую серию, после досмотренной — на следующую. В плеере — кнопки
«Предыдущая / Следующая», лента серий и автопереход к следующей серии через 10 секунд
(Shift+N — сразу). В комнате хост выбирает серию, у всех плеер переключается.

### Видео в панораме слайдера

В карточке, в блоке «Видео в панораме слайдера»: укажите начало (например, `1:12:30`) и
длину 3–45 секунд и нажмите «Вырезать из видео» — фрагмент вырежется прямо из подключённой
раздачи (беззвучный H.264 до 720p, обычно 2–5 МБ) и сразу появится в превью. Можно
загрузить и готовый MP4/WebM до 80 МБ. В слайдере видео крутится по кругу вместо кадра
(кадр остаётся обложкой), играет только видимый слайд, есть кнопка звука; при настройке
«уменьшить движение» в системе видео не запускается. Фильмы с видео идут в слайдере первыми.

### Нагрузка при перекодировании

При запуске сайт проверяет видеокарту (в логе: «Перекодирование видео: видеокарта AMD (AMF)»).
С ней 4K HEVC декодируется, масштабируется и кодируется целиком на видеокарте — кадры не
попадают в оперативную память. Замер на Ryzen 7 7840HS / Radeon 780M, 4K HEVC 10 бит → 1080p:

| | Процессор | Память FFmpeg |
|---|---|---|
| Было | 18,7% всего процессора | 1761 МБ |
| Без видеокарты (`CINEMA_HWACCEL=off`) | 12,0% (4 потока) | 791 МБ |
| Видеокарта AMD (AMF) | 1,0% | 481 МБ |

Если видеокарта не справилась с файлом (например, старый AVI с MPEG-4), задание сразу
перезапускается на процессоре. FFmpeg работает с пониженным приоритетом, не уходит дальше
4 минут вперёд зрителя, а задания, которые после перемотки или смены качества никто не
смотрит, останавливаются.

### Качество и озвучка

В правом верхнем углу плеера — меню «Качество · Озвучка» (и в комнатах тоже):

- **Оригинал** — файл без перекодирования, если браузер его понимает (MP4/H.264, WebM);
- **1080p / 720p / 480p / 360p** — перекодирование на лету (не выше исходного качества;
  4K HEVC, как в сериях «Лучше звоните Солу», браузер напрямую не играет — по умолчанию 720p,
  1080p требует быстрого процессора);
- **Озвучка** — все аудиодорожки файла с языком и названием из раздачи («Русский · Дубляж ·
  5.1», «English · 5.1»). Другая дорожка всегда идёт через перекодирование: браузер в
  оригинальном файле играет только основную.

Переключение — без перезагрузки страницы, с того же места. Выбор запоминается в браузере:
следующая серия откроется с той же озвучкой и качеством.

## Проверки

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v      # 112 офлайн-тестов
.venv/Scripts/python.exe tests/smoke_engine.py                 # движок с настоящим libtorrent
.venv/Scripts/python.exe tests/e2e_browser.py --channel msedge # браузер: плеер + комната + HLS
```

Юнит-тесты и e2e используют эмулятор libtorrent (`tests/fakelt.py`): «раздача» идёт из
локальных файлов с заданной скоростью, поэтому сеть не нужна. `smoke_engine.py` поднимает
второй, настоящий libtorrent-сид на localhost и проверяет каждый байт при случайных перемотках,
возобновление из кеша и скользящее окно (96 МиБ «просматриваются» целиком, на диске остаётся
несколько мегабайт). E2E создаёт временную базу, регистрирует двух пользователей,
публикует фильм через форму и проверяет синхронизацию комнаты (скриншоты в `tests/artifacts`).
Ваши аккаунты и библиотека при проверках не меняются.

## Файлы

- `torrent_stream.py` — движок: общая сессия, планирование частей, чтение, кеш, magnet.
- `torrent_hls.py` — анализ видео, выбор способа доставки, общие HLS-задания FFmpeg
  (варианты по качеству и аудиодорожке).
- `playback.py` — сеансы просмотра, HTTP Range, HLS, прогресс и статистика.
- `rooms.py` — комнаты, SSE, синхронизация, чат, реакции.
- `series.py` — распознавание сезонов и серий по именам файлов, проверка правок админа.
- `torrent_meta.py`, `bencode.py` — разбор .torrent и magnet без libtorrent.
- `services.py` — рекомендации и статистика профиля.
- `library.py` — админка; `accounts.py` — аккаунты и восстановление пароля; `mailer.py` — отправка писем (SMTP или `.local/outbox`); `database.py` — SQLite (WAL).
- `static/js/player.js` — клиентский движок воспроизведения, `torrent-player.js` — страница
  плеера, `room.js` — клиент комнаты, `admin.js` — живая статистика админки.

Данные — в `.local/` (база и ключ сессий), кеш фильмов — в `.torrent-cache/`, загруженные
постеры и видео для слайдера — в `static/uploads/`. Проект учебный: используйте раздачи, на распространение
которых есть права.
